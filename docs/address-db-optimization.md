`address-db-build.json`에 남기고, 실행 중 해당 코드는 영문주소 자동 적용을 거부한다.

## DB 및 실행 정책

테이블은 `admin_names(code, sido, city, district, town, ri)` 하나뿐이다.
건물, 도로, 번지, 우편번호 등의 컬럼은 저장하지 않는다. `WITHOUT ROWID` 복합 기본키 외에
보조 인덱스는 없다. 실행 시 `mode=ro`, `query_only=ON`, 256KiB 캐시로 코드 한 건만 조회한다.
전체 데이터를 메모리에 적재하지 않으며 DB 관리 UI를 제공하지 않는다.

DB는 PyInstaller 내부 자료에 넣지 않고 배포 폴더의
`data/address/english_admin.sqlite`에 별도 파일로 둔다. 원본 Excel 두 파일은 배포에서 제외한다.
시작 시 파일·버전·스키마를 확인하며, 파일 누락/손상 시 국문주소 조회와 편집은 계속 가능하지만
영문주소 자동 적용은 중단하고 상태 표시줄에 이유를 알린다.

## 배포 비교

동일한 소스 환경과 ZIP 압축 조건으로 기존 Excel 포함 빌드와 SQLite 외부 파일 빌드를 비교했다.

| 항목 | 기존 빌드 | SQLite 빌드 | 차이 |
| --- | ---: | ---: | ---: |
| 배포 폴더 | 621,134,473 B | 621,991,068 B | +856,595 B |
| ZIP | 250,225,105 B | 250,163,513 B | -61,592 B |
| EXE | 8,197,165 B | 8,200,640 B | +3,475 B |

기존 배포에는 379,776-byte 구형 주소 Excel이 들어 있었고, 새 배포는 이를 제거한 뒤
1,232,896-byte SQLite를 추가했다. 따라서 폴더는 약 0.82MiB 늘지만 ZIP은 약 60KiB 작아졌다.
420,825,253-byte 신규 원본 Excel을 그대로 포함하는 경우와 비교하면 SQLite는 419,592,357 bytes 작다.

상세 원시 수치는 `address-db-build.json`과 `address-db-packaging.json`에 기록한다.

## 상세주소 정합성

VWorld가 `풍천면 / level5=산128임`처럼 반환하고 전체 주소에 `광덕리 산 128`을 제공하는 경우,
국문 상세는 `광덕리 산 128`, 영문 상세는 `San 128, Gwangdeok-ri`로 같은 범위를 나타낸다.
끝의 `임`은 지목 정보이므로 주소 표기에서 제거한다.

좌표 `36.5264, 128.52435`의 VWorld 결과는 경상북도 안동시 풍천면 광덕리 산 128이다.
전남광주통합특별시 화순군 백아면 와천리 산 120을 의도했다면 그 행의 좌표가 다른 것이므로
주소 문자열을 안동 결과로 덮어쓰지 말고 좌표를 먼저 수정해야 한다.
